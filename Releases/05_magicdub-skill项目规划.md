# magicdub-skills 项目规划

> 规划基线：2026-09-13（项目路线收敛）；具体功能基线沿用 2026-09-12 已确认范围。本文统一截至本轮已确认的项目决定，替代本文件 2026-09-07 版本。它规定应实现的行为，不代表代码、安装、升级或真实译制已经通过验收；当前执行证据见 [CURRENT](../.records/CURRENT.md)。

## 1. 项目定位与边界

`magicdub-skills` 是面向 Codex、主要自用的视频处理技能集，也是 MagicDub 当前唯一主动推进的实现项目。首个业务 skill 为视频译制：使用者提供本地视频，由 Codex 协调自带程序与模型 API，完成转写、翻译、配音、时间轴对齐和视频合成，交付新视频。后续字幕等独立工作流复用同一个视频项目。

| 项目项 | 当前约定 |
| --- | --- |
| 代码仓库 | [shishengkai/magicdub-skills](https://github.com/shishengkai/magicdub-skills) |
| 仓库定位 | 技能集，独立 skill 放在仓库 `skills/<名称>/` |
| 首版入口 | `magicdub`、`magicdub-setup`、`magicdub-upgrader` |
| 使用者与公开 | 主要自用，先完成自用可用版本；最近一次核验为私有，未来是否及何时公开按实际需要另定 |
| 源码许可 | MIT；实现交付时落实 LICENSE 与依赖说明 |
| 首版宿主 | Codex；暂不适配 DeepSeek Harness 或其他 harness |
| 运行程序 | Python 3.12+，uv 管理环境与依赖，FFmpeg / ffprobe 处理与检查媒体 |
| 首批验收 | macOS 完整验收；Windows 原生、WSL、Linux 分别验证后再声明支持 |

仓库中文 description：

> 面向 Codex 的视频处理技能集，围绕视频译制、字幕制作等工作流组织独立 Skill，通过自带程序直接调用模型 API。

2026-09-12 只读回读 GitHub，确认仓库名称、description 与私有状态一致。本次没有审计代码实现程度；上述技术和功能约定不能作为已实现证据。

本项目为运营抖音、YouTube 等账号的视频译制提供工具；首版不包含账号管理、自动上传或平台发布。**永远不做唇形 / 口型修正。**

新程序直接调用供应商 API，不依赖旧 magicdub 引擎、旧 CLI、相邻源码目录或个人虚拟环境。各 skills 共用本项目自身程序，不复制多套配置、费用和媒体处理实现。既有 Web / Cloud 文档仅提供背景，不向本路线继承 dashboard、数据库、队列或某一云平台架构。

### 1.1 整体项目收敛

2026-09-13 用户决定取消 `magicdub-cloud`，原 `magicdub` 暂时保留，当前先完成 `magicdub-skills`。不并行推进旧引擎、Cloud 或对外 Web 产品，也不把这些工程作为 skills 的前置依赖。

未来确有 Web 版对外供用户使用的需要时，再决定重启 `magicdub` 仓库或新建仓库；不预设恢复 `magicdub-cloud`，也不预定 Web 架构或排期。技能集主要自用与未来可能公开源码是不同决定；MIT 及已确认首版功能继续保留，公开分发不是当前可用版本的前置条件。

## 2. Skill 划分与交互

| Skill | 负责什么 | 与其他入口的关系 |
| --- | --- | --- |
| `magicdub` | 视频译制、任务语言与模型选择、步骤进度、结果和费用报告 | 只保留简短环境预检、维护路由和任务结束版本检查规则 |
| `magicdub-setup` | 首次安装、运行依赖、交互配置、配置修改、自检和未完成设置恢复 | 已完成的配置不重复询问；重复 setup 不等于升级 |
| `magicdub-upgrader` | 检查稳定版本、按用户指令升级、升级恢复和验证 | 完整升级指令按需加载；与业务程序共用版本与安装记录 |

每个入口有独立 SKILL.md；用户可用自然语言表达意图，不必记住或手动切换 skill 名称。维护任务按需进入相应 skill，避免把安装、升级长文合并到译制主指令。

首版交付上述三个入口；字幕 skill 紧随后续迭代，不按内部 pipeline 阶段机械拆分更多 skill。未来需要 plugin 分发时可封装这组 skills 和共享程序；plugin 不是首版前置条件。

### 2.1 首次安装配置

README 提供简短入口，例如“请安装并配置 MagicDub”并附仓库地址。首次安装由该入口引导 Codex 获取同一版本的 setup 指令和程序，不能依赖尚未安装的 skill 已自动触发。仓库 `skills/` 是源码组织方式，实际安装位置与宿主发现机制需要验证。

setup 连续完成：

1. 识别实际执行系统、已有安装和配置，检查 Python 3.12+、uv、FFmpeg / ffprobe 与所需目录。
2. 复用兼容依赖，准备缺失运行环境；不替换系统 Python 或改动无关软件。
3. 提供可见的视频项目位置选项，复用用户已有选择；全局配置、安装与视频项目目录分离。
4. 只补齐当前启用服务所需凭据，已有的不再索取；通过可用的受保护入口或本地凭据文件填写，程序只返回状态。首版宿主 LLM 不需要额外 LLM key。
5. 验证依赖、配置、路径和入口实际可用，明确尚待真实 API 调用验证的能力，再交付下一步。

交互使用 Codex 对话，不要求先开发配置网页或 Web server。中断后只补未完成步骤，修改配置只改相关项，保留视频资料。用户同时要求安装和译制时，设置完成后继续原视频任务；单纯安装不自动发起付费生成。

## 3. 首版译制流程与模型选择

### 3.1 执行前

- 读取本地输入和已有项目；缺少源语言或目标语言时提供选项，已经明确的选择直接沿用。
- 首版就提供已接入候选模型的选择，不将全部模型选择后置到未来版本。多个候选的环节展示选项，单候选显示实际采用值即可。
- 显示实际供应商、模型和必要能力差异；确认所选组合支持任务语言、声音参考、多人和输入长度。候选模型名单不是已经接入或验证的声明。
- 保存本次模型、参数和执行版本，不静默切换模型；更换模型需取得对应选择。
- 原视频复制到视频项目后处理，原件、已有中间结果和已有成品保留。

### 3.2 已确定的候选范围

| 环节 | 候选 / 策略 | 实施要求 |
| --- | --- | --- |
| ASR | fal Whisper `fal-ai/whisper`；阿里云百炼 Fun-ASR | 同时按候选选项设计；Fun-ASR 具体版本、地域、参数及各模型说话人能力需实测 |
| 音频分离 | fal Demucs `fal-ai/demucs`；SAM Audio `fal-ai/sam-audio/separate` | 提供选项，验证对白、背景声和声音参考的产物质量 |
| 翻译与时长措辞调整 | 当前 agent 自带 LLM | 先实测效果，再决定是否另行指定模型 / API；不预设独立 LLM key |
| TTS | fal IndexTTS 2 `fal-ai/index-tts-2/text-to-speech` | 按说话人提供声音参考，先验证任务语言、音色与短片段使用效果 |
| 媒体中转 | fal CDN、百炼临时存储 | 未指定唯一默认服务，按模型可访问性匹配 |

Fun-ASR 的调用规则已确定：可访问 HTTPS 媒体地址采用 SDK；百炼 `oss://` 临时地址采用 REST 并使用所需资源解析请求头。更换传输方式不等于更换模型。具体访问有效期、账号与接口可达性在实现时验证。

### 3.3 主 pipeline

| 阶段 | 输出和责任 |
| --- | --- |
| 输入准备 | 复制并核验源视频，读取媒体信息，保存所选音频来源与时间轴 |
| 音频分离 | 获得对白 / 人声与可混回的背景音乐、环境声 |
| 转写与说话人整理 | 保存原文、句子时间范围、稳定说话人关联和声音参考 |
| 翻译 | agent 依据原文、上下文与时长要求生成译文，程序校验并落盘 |
| 配音 | 使用所选 TTS 和对应说话人参考生成片段，逐次记录调用和费用 |
| 对齐 | 将各句配音强制拉伸 / 压缩到对应原句时间窗口 |
| 混音与导出 | 配音与背景轨按原视频时间轴合成，交付新视频、项目位置与报告 |

首版保留多人对话、声音克隆和背景音乐保留要求，当前优先跑通普通短视频的完整译制闭环。多音轨分别译制、逐声道处理与空间回填、约两小时电影处理均延后，不作为近期实现或验收要求；未来是否开展及具体路线按实际需要再决定。多人及声音一致性先在短片段中验证，不以保存 speaker_id 字段替代能力验证。

程序和 agent 通过可校验的阶段产物交接文本。一次发起自动译制不要求单个 Python 进程自行调用宿主 LLM；具体分批文件协议仍需定稿。业务执行状态与文本产物必须落盘，不能依赖完整聊天记录一直存在。

## 4. 译文、质量与失败处理

- 译文忠实原意、自然口语，保留关键事实、数字和人物关系；为适应时长先调整措辞与停顿。
- 首版最终逐句强制匹配原句时长，轻微变速不是硬性上限；所需伸缩影响自然度时仍自动继续，并在报告中说明。
- 对齐以原视频时间轴为基准，不通过改变整部视频速度替代逐句处理，也不把截掉后半句作为时长对齐。
- 有可用结果的质量或对齐问题不暂停请求用户裁决；保留质量标记和已完成结果，不静默切换模型。
- 重试有明确有限次数；不无限请求翻译、重新生成 TTS 或重复提交云端任务。
- API、下载、解码或合成在有限重试后完全没有可用结果时，如实报告技术失败、保留状态与费用；“质量问题继续”不能变成伪造成功。
- 导出成功与主观质量分开报告。质量评估继续进行，但首版不因主观不理想新增人工审校关卡。
- **首版不设置任务预算、金额上限、预算确认或超预算暂停。** 逐步费用记录和结束汇总仍为必需能力。

## 5. 项目数据与存储

### 5.1 三类位置分开

| 位置 | 内容 |
| --- | --- |
| skill / 程序安装目录 | 指令、程序、依赖声明、静态资源和版本信息 |
| 用户级配置目录 | 供应商凭据、普通全局设置与安装维护状态 |
| 可见的视频项目目录 | 复制的源视频、原文、译文、时间轴、声音参考、中间产物、执行记录、费用和成品 |

用户可指定视频项目位置，包括自己的工作区或外接存储。中间产物与成品归属于同一视频项目；修改过的译文和时间轴是项目资料，不作为普通临时缓存删除。具体系统默认路径仍待实施定稿，不能把讨论过的 `~/.magicdub/` 示例直接解释为所有视频的固定存放位置。

路径以实际执行环境解析，区分 Windows 原生与 WSL；CMD 和 PowerShell 的语法差异不代表两套原生 Windows 项目目录。跨系统共享和迁移不能在未验证时宣称自动可用。

### 5.2 共享数据契约

项目至少保存：

- 项目格式版本、原素材身份与位置、源语言、目标语言。
- 稳定的句子编号、说话人关联、原视频时间范围、原文和译文。
- 实际采用的供应商、模型、参数与程序版本。
- 各阶段状态、成功产物位置、失败位置和可定位的执行记录。
- 每次尝试的费用及其币种、来源和核实状态。

原视频使用副本；需要保留的远端结果下载到项目，临时 URL 不充当长期素材。视频项目能独立于聊天存在，并可供后续字幕和审校使用；供应商私有响应不直接成为跨 skill 唯一的数据协议。

文件名、JSON / JSONL 字段、修订号、锁与精确迁移机制保留在技术 Draft，尚未作为逐字段定稿。实现时需要验证项目移动、恢复与产物关联，不以“文件已经写出”宣称全部恢复能力完成。

### 5.3 阶段结果与后续修改基础

按当前短视频输入和所选模型限制安排必要分块与有限并发，保存时间映射、说话人关联、声音参考与上下文。暂不为长片、多音轨或逐声道译制预建调度与声场处理体系；产品长期时长上限未定。

保留成功结果与所有已有导出。修改原文或译文后，相关配音、对齐和成品的有效性必须能重新判断；未来重做应只作用于受影响范围。断线后优先通过已保存请求编号核对状态，不能默认再次提交。具体“停止 / 继续 / 重做”的用户契约仍待定稿。

## 6. 费用统计与结束报告

每个步骤、每次外部执行尝试记录费用，包含成功、失败、取消和结果尚不明确的调用。失败步骤已花掉的钱计入本次任务和项目累计，不能在重试成功后删除。

- USD 与 CNY 独立计算，界面展示 `$1.20 + ¥3.40`；`$` 为美元，`¥` 为人民币，加号表示并列，不自动换汇。
- 每项费用能够关联具体任务、阶段与请求 / 尝试；重复查询、估算转实账和重试统计不得重复累加同一收费。
- 费用需区别已确认、估算和待核实；未知金额不是零。缺乏账单权限或尚未回传账单时，报告现有汇总和待核实项。
- 本次新增费用与项目历史累计区分；费用统计覆盖失败尝试及与任务直接相关、能够归属的其他费用。
- 宿主 LLM 费用无法独立计量时注明未纳入，不能写为免费或将外部 API 小计冒充所有成本精确总额。
- 成功、失败或正常取消结束均交付状态、可用产物位置和费用报告；强制中断来不及输出时，在后续读取项目时补出。

首版结束报告至少包含任务状态、成品或已有产物位置、本次费用、其中失败尝试费用、估算 / 待核实项及统计覆盖范围。具体账本格式、对账接口权限和维护任务费用记录方式按技术方案实现验证。

## 7. 更新与可选 Star

### 7.1 更新

自动版本检查与升级分开：任务完成后进行轻量检查，有新版才提示；用户明确要求升级后连续完成普通升级，不重复确认同一授权。没有新版或自动检查失败不影响已经交付的任务；显式查询失败如实说明。

更新来源固定为 `shishengkai/magicdub-skills` 的稳定发布；核验实际版本后安装，保留配置、视频项目、费用记录与可恢复旧版本。正在执行的任务不得混用新旧程序；具体并存或切换机制在实现时验证。开发 checkout 不被普通升级覆盖，未来 plugin 安装交由宿主相应机制管理。

仅下载新代码不代表宿主已加载新版；完成报告须验证实际生效状态。具体发布清单、校验字段、检查间隔与安装命令仍在 Draft，不新增常驻检查服务。

### 7.2 Star

首次安装配置全部成功或真实升级成功后，复用公共规则判断是否发出可选 Star 邀请；不独立创建 Star skill，不在普通译制或配置修改中反复邀请。

邀请可以忽略，不影响功能、升级或成品；已 Star、缺少工具 / 认证或无法可靠判断时跳过自动邀请，不为此要求安装工具、登录或提交凭证。真正执行 Star 前明确账号和 `shishengkai/magicdub-skills` 仓库，取得对应同意后执行并回读。安装、升级或继续译制的同意不代替 Star 同意。

具体频率控制与本地偏好存储方式保留在 Draft；这项功能规划不授权当前任务实际执行 Star。

## 8. 后续迭代与首版范围之外

| 阶段 | 交付重点 |

## 9. 首版验收

必须使用新项目自身程序与真实 API。旧 magicdub 历史结果、模拟输出、文档或单独的安装自检均不能替代完整译制验收。

| 指定素材 | 方向 | 已核验媒体信息 |
| --- | --- | --- |

## 10. 实施顺序与尚待定稿

先落实三入口和最小运行环境、共享项目 / 费用协议，再用现有素材的短片段验证所选 ASR、分离、TTS 与 agent 翻译的组合，完成新视频导出和费用汇总。短片段跑通后再安排原指定完整素材回归；根据实际使用完善恢复和后续字幕 / 审校，不提前展开长片、多音轨或逐声道方案。

仍需在实施设计中确定：各系统默认目录与安装来源，模型版本 / 地域 / 参数和默认选项，重试次数与并发量，数据字段和锁，费用对账权限，停止 / 继续 / 重做的具体契约，配置优先级、清理卸载边界和普通视频导出格式。

用户在 2026-09-12 明确决定先不做音轨 / 声道的高级处理，先跑通短视频。此前“每个音轨、每个声道独立译制后合并”及其替代方案仅保留为未来参考，当前不继续选型或验证；约两小时长片也不再作为近期目标。该范围收敛不撤销多人、声音克隆、背景保留和费用统计要求。
