# 使用环境变量成功验证 MVSEP 个人队列摘要

## 结果与更正

用户明确要求使用环境变量中的 API Key；改为从当前进程 `MVSEP_API_KEY` 读取后，两个接口均返回 HTTP 200。前条中本机凭据文件遭拒的观测仍成立，但“账户层实测待有效凭据”的阻塞已解除；环境变量是本轮认证成功的来源。未修改凭据文件，未保存密钥，未创建分离任务。

2026-10-01 22:24:00～22:24:01 +08:00 的直接 GET 返回：

- `/api/app/queue`：`queue={in_process:23,premium:54,registered:58,unregistered:73}`，等待合计 185，另有 23 正在处理；`current={plan:"registered",queue:58}`；`free_separations={left:50,max:50}`。
- `/api/app/queue/summary`：`success=true`，`data={queued:0,processing:0,ahead:0,estimated_wait_seconds:null,throughput_per_min:30.3}`。

## 字段解释与边界

公共队列按套餐返回等待数，`current.queue` 是当前套餐等待数，不是个人位置；`free_separations` 提供剩余/上限，本接口未返回额度重置时间。实际套餐容器叫 `current`，与文档表格中的 `plan` 命名不一致。

个人摘要提供本人排队数、运行数、最早排队任务前的同层级任务数 `ahead`、到开始处理的保守估时（秒）及全集群近期每分钟领取任务数。`null` 表示无法给出估时；本次本人无排队任务，不能将 `ahead=0` 当作排在第一，也不能将 null 当作无需等待。没有逐任务 hash/位置列表或处理完成 ETA。

官方队列说明为 Premium 优先、Registered 次之、未登录最后；不能简单用全站排队数除以全集群吞吐率来保证免费任务等待时间。本轮快照并不验证日内拥堵规律、非空等待估时准确度或地区队列范围。
