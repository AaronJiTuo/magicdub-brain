# 核验 MVSEP 队列接口与个人摘要认证限制

## 结果

- 对用户指定的两个接口执行只读 GET，未创建分离任务、未切换套餐或修改凭据。
- 2026-10-01 22:22:34 +08:00，`/api/app/queue` 返回 HTTP 200：`queue.in_process=24`、`premium=0`、`registered=1`、`unregistered=16`；等待合计 17，另有 24 正在处理。这是瞬时快照，不代表日内趋势。
- 实际个人套餐容器为 `current`（文档表格写作 `plan`），另有未在该接口字段表列出的 `free_separations.left/max`。本轮返回 `current.plan=unregistered`、`current.queue=16`、`free_separations={left:50,max:50}`。
- 无密钥请求个人摘要返回 401；本机 MagicDub skills 与 CLI 的现有 MVSEP 凭据相同，带密钥请求 `/api/app/queue/summary` 也返回 HTTP 401，正文为 `success=false`、`errors=["invalid token"]`、`data.message="invalid token"`。因此不能将公共接口的 50/50 解释为用户账户额度，也不能用其 HTTP 200 证明认证成功。

## 文档能力与边界

官方文档列出个人摘要字段：`queued`（本人排队数）、`processing`（本人运行数）、`ahead`（最早排队任务前同层级任务数）、`estimated_wait_seconds`（到开始处理的保守估时，未知为 null）、`throughput_per_min`（全集群近期每分钟领取任务数）。该接口要求 `api_token`；本轮未获得认证成功响应，未实测个人位置、估时与完整成功响应结构。

`ahead` 并非全站绝对排名；预计等待不包含分离处理耗时。全站队列长度不能直接换算个人等待时间。两个接口未提供逐任务 hash/位置列表、额度重置时间或历史拥堵曲线的已验证数据。

## 后续与项目影响

需要有效 MVSEP 凭据才能完成账户层实测；需要实际存在排队任务才能验证非空估时及位置变化。当前不修改 CLI、skills、既有任务或 Release。证据为上述稳定接口的直接 HTTP 返回及官方 API/队列说明，本记录不保存密钥或认证 URL。
