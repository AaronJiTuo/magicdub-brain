# CLI 时长改写缺少目标译文上下文与语义选稿

## 结果

用户报告：后两轮为适配时长而修改译文后，部分句子与上下文衔接变差，成片听起来异常。本轮只读核查代码，确认以下机制；用户所指具体成片尚未逐句复现，不能将全部质量问题归因于这些机制。

- 每轮翻译实际已传入全文原文 `src.transcript`；不能表述为“程序完全没有全文上下文”。
- 重译负载只有待修改句的原文、目标时长及本句被拒绝的历史译文与 TTS 测量；没有其他句子已采用的译文、完整当前译稿或结构化相邻句译文。API 请求每次重新构建，不保留上一轮完整译稿作为会话上下文。
- 改写提示词要求保留含义、意图和事实，但主目标为接近单一 `target_duration_ms`；未传入可配置的合格区间，也没有明确约束跨句指代、连接词配对、术语一致性或最小修改。
- `apply_attempt_selection` 仅按时长比例判断通过；`closest_attempt` 按距合格区间、距 1、attempt 编号排序。没有语义或衔接检查；各句独立选稿后直接 alignment／mixing，没有最终整篇译稿检查。
- 本机安装的 translation slot、DeepSeek translation adapter、pipeline runner 三个文件与上述 checkout 的内容摘要一致。

## 证据与成果位置

关联代码提交 `7c576d751d08a513f10768f1d56eb1867c2572e3`：

- `src/magicdub_cli/steps/slots/translation.py`：第 29–82 行，请求负载与 history。
- `src/magicdub_cli/adapters/translation/deepseek_deepseek_flash/__init__.py`：第 34–115 行，改写指令、全文原文与消息构建。
- `src/magicdub_cli/pipeline/runner.py`：第 106–161、197–227 行，轮次编排与选稿；第 53–66 行，选稿后直接对齐与混音。

## 对当前项目的影响

后续处理这类问题时，应同时检查目标语言上下文、受约束改写和选稿标准；单纯再次添加全文原文不能补齐上述缺口。`duration_fitting` 本身仅测时长和比例，翻译在 adapter、选稿在 pipeline，不能把职责混入测时长步骤。

## 未完成与下一步

当前译稿快照、最小修改约束、语义检查与最终拼稿检查均为讨论中的候选改进，未获选定、未实施，未改变 Release。需要从实际问题任务固定原文、各轮译文、音频与时长，比较衔接、忠实度、时长达标率、变速幅度和费用；本轮没有新增模型请求、运行新译制、修改 CLI 或升级日常安装。
