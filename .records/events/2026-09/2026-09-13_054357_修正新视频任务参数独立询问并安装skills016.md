# 修正新视频任务参数独立询问并安装 skills 0.1.6

## 原因与决定

- 用户实测截图显示，处理新的 cnn.mp4 时直接沿用了前面视频的语言与模型并开始调用；这是用户反馈，未重新执行该视频。
- 旧 skill 的“已明确的选择直接沿用”没有限定当前视频，允许把历史选择误当作本次参数。用户明确要求每个视频独立、每次询问。

## 实现与交付

- 新视频每次实际展示译制方向、ASR、人声分离三题，题目带本次文件名，等待提交后才创建项目及调用模型。历史、记忆、安装默认及新请求中提到的参数仅用于推荐排序，不能跳过本次交互。
- 已提交回答只适用于当前视频；同一会话的新视频也重新询问。明确指定批次共用时才可共用该批次本次选择。
- 明确继续同一已有项目则沿用该项目参数；同名视频不自动续跑历史项目。分批翻译、失败重试与断点恢复不重新询问。
- 更新主 skill、共用交互规范和 README，版本 0.1.6 已提交、推送并从 GitHub 安装；Codex 实际发现并启用精确提交下的三个入口。

## 验证与边界

- 主 skill 结构校验、三题 JSON 示例、原有普通密钥输入示例、manifest 和差异检查通过。
- 本次只调整交互指令，未更改媒体程序或模型内部参数，没有新增付费调用；不通过新增单元测试来代替 agent 交互验收。
- 尚未实测新视频的用户点选及后续执行，不能据结构校验宣布实际交互验收通过。未修改用户正在运行的旧视频项目或其固定版本。
