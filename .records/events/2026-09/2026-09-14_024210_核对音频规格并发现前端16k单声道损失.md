# 核对音频规格并发现前端 16 kHz 单声道损失

## 当前事实

已读取本机正式安装 v0.2.0（fa7f23b）及本地 0.3.0 候选，两者的音频规格链相同。本次只读核对业务代码，不修改音频参数或运行付费调用。

- prepare 从原视频首音轨提取 PCM 16-bit WAV，并强制 16 kHz、单声道。PCM 解码不增加有损编码，但降采样和声道合并会丢失信息。
- 分离输入使用这份 16 kHz 单声道音频；Demucs 配置 WAV，SAM 配置 MP3。返回文件保存后再统一转为 16 kHz 单声道 PCM16 人声。
- 背景由上述低规格原音和人声相减得到，亦为 16 kHz 单声道 PCM16；TTS 的声音和情绪参考都裁自这一人声。
- IndexTTS2 未传输出格式/采样率参数，下载程序仅保留响应字节，以 wav 后缀保存，不能仅凭后缀认定实际编码。当前 fal 文档没有开放这两项输出控制。
- 对齐输出 PCM16，保留 TTS 采样率；混音统一 48 kHz 单声道 float32 WAV，成片 AAC、目标 192 kbps。后端升采样无法恢复前端已丢失的信息。

## 文件级实测

既有 Steve Jobs 90 秒验收项目：原视频 AAC 44.1 kHz 双声道约 128 kbps；分离原始返回 WAV PCM16 44.1 kHz 双声道；本地处理后的人声、背景、声音参考皆 16 kHz 单声道 PCM16。目录中 22 份 TTS 及 22 份对齐文件（含修订历史）均为 WAV PCM16 22.05 kHz 单声道。混音 48 kHz 单声道 float32；最终 AAC 实际约 139 kbps，不能将目标 192 kbps 说成实测码率。

fal 文档：Demucs、SAM 均支持 WAV/MP3；SAM 输出 sample_rate 字段默认/示例为 48000，但未新增请求验证其当前真实输出。IndexTTS2 示例和 schema 不能替代真实文件探测，实测仅代表已有项目。

## 建议与边界

建议原音母版保留原生采样率及声道；模型输入仅按必要限制转换。分离统一选 WAV 并保留模型原始返回；ASR 如需 16 kHz 单声道，单独派生副本，不回用于背景和 TTS。TTS 参考采用高品质分离人声，输出保留模型原生规格；中间计算使用浮点 PCM，最终交付时才有损编码。

这些是待确认实施的建议，不宣称已调整或听感验收。立体声保留不等于逐声道独立模型处理，不擅自恢复已延期的复杂音轨方案。已完成项目使用缓存，优化若实施应显式区分旧缓存及新参数，不能只改参数后宣称老成品升级。
