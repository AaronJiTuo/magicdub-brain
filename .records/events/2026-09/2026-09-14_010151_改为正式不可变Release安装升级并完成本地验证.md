# 改为正式不可变 Release 安装升级并完成本地验证

## 决定与实现

- 用户要求按 brain-template 的版本发布和升级逻辑修改 MagicDub。0.2.0 候选改为遍历正式 GitHub Releases，过滤 draft、prerelease 和非标准 vX.Y.Z，按 SemVer 先选最高项，要求 immutable=true，再完全解引用 tag 到精确 commit，核对该 SHA 的清单来源、stable 通道、版本和文件摘要格式。
- 最高候选验证失败时停止，不回退旧版或 main。版本检查只读，不再写检查缓存，也不下载远端程序；安装器验证完整文件、锁定环境和实际版本后切换入口。升级再次绑定 tag 与预期 commit，不降级，保留旧快照及用户数据。
- 开发 ref 必须与 --development 同时明确指定；本地验收快照和远端开发快照不作为稳定安装，不参与普通自动升级。恢复指定版本也要求正式不可变 Release。
- README、setup、upgrader 与 docs/releasing.md 同步了正式发布流程；版本号和 release.json 已准备为 0.2.0。Star 授权保持独立，本次没有改动媒体处理和模型参数。

## 验证

- 52 项自动测试和 Ruff 通过，包含多页排序、附注 tag、无效最高版本不回退、清单不匹配、路径与摘要格式、无发布时停止、预期提交不匹配、禁止降级和只读检查。
- setup / upgrader 结构校验、manifest 与差异检查通过。
- 隔离集成验证使用模拟 Release API 元数据、真实本地 Git tag/commit 和真实 uv 锁定安装：0.2.0 安装后升级到 0.2.1，忽略未发布的 0.3.0 main，拒绝清单损坏候选并保留原安装；凭据、配置、视频项目和旧快照保持不变。此项不是线上正式 Release 验收。
- 实际 GitHub 查询确认当前没有正式 Release，且仓库 immutable releases 设置为 false；新发现程序返回 no_stable_release，没有转用 main。未修改 GitHub 设置，未创建 tag 或 Release，没有付费模型调用。

## 交付状态与迁移边界

- 本次代码与 brain 记录均留在工作区，尚未 commit / push 或正式发布。
- 本机仍为已安装的 0.1.6（2ddb439）；其旧更新器仍读 main。用户此前已反馈当前版本自己可以使用，但不能据此补造所有 UI 或平台的验收。
- 后续需在授权后开启不可变发布、发布首个正式 v0.2.0，再用新安装器迁移现有安装。新版本只认正式 Release 的规则须迁移后才在日常使用中生效；单纯修改仓库代码不能改变旧快照行为。
