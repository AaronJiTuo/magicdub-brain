# 确认 Fun-ASR 统一处理后上传

## 决策

用户明确确认：“既然是这样，那就统一都处理之后再上传给fun-asr吧，确定这个决策”。结合前一轮已核对的处理规格，统一流程为：分离人声 → 16 kHz、单声道、PCM16 WAV 的 ASR 专用副本 → 上传 → Fun-ASR。

所有分离结果均走这条处理链，媒体 URL 必须指向处理后的副本；可复用与当前人声内容及处理规则一致的缓存。高质量分离人声继续保留供声音参考与混音使用，ASR 副本保持完整时间轴，本决策不增加去静音、裁剪或额外增强。

该决定收敛此前对直接提交分离原件的讨论，依据是统一输入和满足开启说话人分离的单声道要求。未取得原采样率与 16 kHz 同源比较证据，不把更高识别准确率作为已验证事实。

## 落地与边界

已将规则写入正式规划第 3.2 节及 CURRENT。本次仅吸收用户确认和前一条参数／音频边界记录，没有消费或归档其他 Draft。

只读核对当前 magicdub-skills 的 audio_quality.asr_audio 与 fun_asr.transcribe：默认链路已有上述派生副本处理并在上传前调用，因此本轮无需新增业务代码修改。显式提供的媒体 URL 仍需由调用方确保对应处理后的副本，不宣称程序已验证远端媒体规格。

音频处理与上传服务路由独立；百炼上传自动集成仍待实施。本轮没有改动凭据、默认模型、旧项目、安装或发布状态，没有新增模型调用、Git 提交或推送。上一轮参数修改仍为本地未发布状态。
