# iiilab 下载按钮直指 Googlevideo，客户端标识与当前 TikHub 不同

## 直接观察

用户反馈 iiilab 网页能正常下载，并要求检查处理方式。在用户已打开的解析结果中读取真实可见链接及 DOM 属性；视频为 1zwJvGENvyU，约 772 秒。

下载按钮 href 均为 HTTPS redirector.googlevideo.com/videoplayback，target=_blank，并设置 download 文件名。链接已经包含格式编号、时效、签名及 pot 参数。可见入口指向 Google 媒体服务，不是 iiilab 的文件中转地址；站点也声明不存储视频及图片。未审计不可见的服务端实现，不能据此前端信息声称掌握完整解析算法或最终重定向链。

页面当前提供 2K WebM（itag 271，链接声明 495,157,856 字节）、1080p MP4（137）等，以及两份英语原声音轨（140、251）。两个音频按钮均设置 iiiLab.mp3 文件名，但目标 MIME 分别为 audio/mp4 和 audio/webm，不能把下载文件名当实际编码或容器。未下载并完整探测这些文件。

本页全部媒体地址 c=TVHTML5_SIMPLY。只读核对前两次 TikHub 缓存，strategy=pytubefix_mweb、所有独立流 c=MWEB。客户端标识差异已确认，差异导致 403 仍是待验证假设；不是同一个视频的受控对比，也不能声称直接改 c 参数或改浏览器即可修复。

## 浏览器测试与边界

通过浏览器提供的下载操作触发第二份音频下载，操作返回但无最终文件路径或完成校验；网页仍显示原解析结果，默认 Downloads 中未找到对应文件。完整下载成功仍仅为用户反馈，不提升为本轮 agent 验收通过。

无新增付费 API 调用，无代理或程序参数修改。未保存签名 URL、Cookie、节点或 API 凭据，未提交、推送或发布。
