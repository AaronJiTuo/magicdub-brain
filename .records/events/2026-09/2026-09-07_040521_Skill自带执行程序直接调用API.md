# MagicDub Skill 自带执行程序，直接调用供应商 API

## 结果

- 按用户明确提出的“直接通过 skill 自己的程序调用 API 来实现”，新 skill 自带完整译制执行程序，不把现有 magicdub 引擎作为运行依赖。
- 首版不采用安装旧引擎、调用旧 CLI、导入旧项目代码包或通过相邻仓库路径执行 pipeline 的方案。
- 程序语言仍在选型讨论；当前 agent 推荐 Python，尚未作为用户确认的技术栈落定。

## 对后续工作的影响

- 新项目负责自身的 API 调用、流程执行、中间产物、任务状态与恢复逻辑，并将执行代码随 skill 一起分发。
- 外部供应商 API、语言运行时及必要的媒体处理工具属于明确声明的依赖；独立实现不等于没有第三方依赖。
- 既有 magicdub 仓库不因本决定被修改、迁移或废弃。此前复用旧引擎的讨论建议不再用于新 skill 的实施规划。
- 首版只支持 Codex、早期自用且未来较大可能公开的既有范围继续有效。

## 未完成

- 尚未创建新代码仓库、编写或安装 skill，也未调用付费 API 验证新的端到端流程。
