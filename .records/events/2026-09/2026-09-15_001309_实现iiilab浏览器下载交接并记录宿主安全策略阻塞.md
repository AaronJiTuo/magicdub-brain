# 实现 iiilab 浏览器下载交接，当前宿主安全策略阻塞下载

## 结果与用户决定

用户要求默认下载方式改为 Codex 内置浏览器打开 iiilab，从可见分离链接取得最高品质音视频，然后自动进入 magicdub，避免重发两份文件或解释文件关系。代码仓库已本地实现；未提交、推送、发布或切换日常安装，正式稳定版仍为 v0.5.0 / `ffb0e31890ece9f2bf451652446b5e7b0c44d456`。

- 下载 skill 默认使用 iiilab 浏览器路径，TikHub 仅保留用户明确指定的旧 API 命令，不作为浏览器拒绝后的后备路线；浏览器下载不要求供应商 Key，本地导入环境与宿主浏览器能力分开检查。
- 新增 `plan-browser-download`，从可见、去除签名 URL 的元数据中选择最高已知规格与原声音轨；多语言不明确时展示本次音轨选项，禁止在续跑时静默换低规格或混用视频。
- 新增 `import-browser-download`，检查完成文件的字节数、实际容器／规格、整段严格解码、时长差及起点差，通过后归档并生成 asset.json。外部文件只归档一次且原件保留；主流程仍在同目录原地使用完整独立视频，不先合并再拆分。格式不符、损坏、同步不符不标记 ready。
- 新增浏览器阻塞状态；两个 skill 自动传递本视频参数、工作意图与素材清单，在同一任务继续。每个新视频仍独立提交译制方向、ASR、分离模型，后续无需额外“开始”或交接确认。

## 实测证据与阻塞

- 实际内置浏览器打开 iiilab，并解析 RwMuIYudhAw，看到 1080p 独立视频及 AAC 音频选项。对最高视频执行公开的 downloadMedia 时，工具的站点安全策略拒绝 Googlevideo 下载目标，并明确禁止用其他工具、原始 CDP、其他浏览器或间接方式绕过。没有尝试绕过；此次拒绝未发起用户授权提示或自动批准审核。未取得新完成文件，**不能宣称浏览器下载或全流程已通过**。
- 166 项测试通过（39.94 秒），Ruff 通过；新增 14 项覆盖格式／音轨选择、任务绑定、拒绝状态、容器纠正、文件损坏、同步、路径限制及主流程交接。合成素材真实 FFmpeg 导入后 pipeline.create 原地复用视频，没有调用模型。
- 使用此前已保存在本地的 RwMuIYudhAw 视频 18,705,683 字节和音频 4,255,891 字节，完整严格解码、归档、asset 校验和重复导入通过，原件及归档后字节哈希一致。这只是历史本地素材验证，不是本轮浏览器成功下载；没有创建真实译制项目，没有新增付费 API 请求。
- 本地隔离安装四入口和 47 个分发文件哈希通过；说明与引用链接校验通过。详细证据在代码仓库忽略目录 `acceptance-local/iiilab-browser-handoff-20260915/` 的 verification.json、install-verified.json。代码中的 docs/acceptance.md 记录边界。

## 当前影响与下一步

默认浏览器规则尚未进入正式版本或日常安装，规范性 Releases 未重写，CURRENT 标记漂移。用户期望的“只提供链接即拿到成片”在当前宿主仍被浏览器安全策略阻塞；本地交接实现与测试不能替代该验收。只有宿主允许相应下载并能提供已完成文件路径时，才继续验证浏览器全链路；不反复重试已拒绝动作，不把历史直连下载当作绕过方案。已有合法本地文件仍可按本地导入处理。
