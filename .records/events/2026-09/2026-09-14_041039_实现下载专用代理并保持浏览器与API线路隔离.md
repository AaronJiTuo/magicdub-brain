# 下载专用代理：媒体线路与浏览器、API 分离

## 用户要求与结果

用户有洛杉矶节点，使用 Quantumult X；要求仅下载程序使用该节点，保留浏览器日常纽约线路，不把 googlevideo.com 全局改走洛杉矶。

代码仓库本地候选已增加可选 MAGICDUB_MEDIA_PROXY，经普通输入框／save-credentials 标准输入保存到用户凭据文件，可显式清空。支持 HTTP、HTTPS、SOCKS5、SOCKS5H；节点分享链接不是代理监听入口。下载媒体使用专用 Requests Session，忽略环境代理、NO_PROXY、netrc，所有媒体重定向维持专用代理，失败不直连；TikHub、fal、百炼保持原路径。无效地址在付费前阻断；doctor／报告不输出代理地址或认证内容。依赖锁增加 PySocks。

## 验证

30 项下载、配置和代理测试通过，Ruff 与 setup skill 结构校验通过。覆盖真实本机 HTTP CONNECT、代理与 API 隔离、重定向、完整受控媒体下载、失败不回退、配置脱敏／清空。说明、README 与 release 清单同步。

没有修改 Quantumult X 策略／系统代理，没有读取浏览器 Cookie，没有启动额外代理内核，没有新增付费 API，没有 Git 提交、推送、Release 或日常安装。

## 仍需完成

Quantumult X 官方示例未找到每个独立监听端口固定不同节点的配置；这不是已证明所有版本均不支持的结论。可由独立本地转接进程复用洛杉矶单节点，禁用 TUN／系统代理接管，或直接使用已有 HTTP／SOCKS 入口。

已询问洛杉矶节点协议／单节点分享信息，等待后才能配置真实出口。洛杉矶出口、CDN 403 修复、完整原片与原声、真实素材交接尚未验收；本地代理隔离通过不能代替这些验证。未读取或保存整个订阅。
