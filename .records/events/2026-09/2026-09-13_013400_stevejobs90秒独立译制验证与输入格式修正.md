# stevejobs 开头 90 秒完成独立 API 译制技术验证

## 结果

- 在独立 Draft 原型中使用 Python 3.12、uv、FFmpeg，完成 Whisper 转写、当前 agent 翻译、SAM Audio 分离、IndexTTS 2 配音、强制对齐及 MP4 导出；未导入或运行旧 MagicDub 引擎。
- 用户先选择 Whisper、Demucs，后要求按旧项目查参数并明确改选 SAM Audio。最终采用旧项目的 16 kHz 单声道分离输入，以及逐句原声同时作为音色 / 情绪参考。
- 14/14 句音频非静音且样本数匹配；视频完整解码，逐帧画面与原片段一致；自动语言识别为中文，回转写覆盖 14 句核心译文。4 句因放慢触发质量提示，未阻断导出。
- 费用记录保留全部 40 次模型请求，含废弃结果和补验；已知费用估算小计 `$0.86 + ¥0.00`。1 次 HTTP 422 失败金额未知；当前 key 读取账单返回 403，不能给出已对账总额，未计宿主 agent 未计量费用。

## 关键发现

- 初次 Demucs 参数与服务端默认 stems 不匹配，发生 422；修正后虽成功，随后按用户选择弃用。
- 48 kHz 双声道输入的 SAM 调用返回近乎静音的人声，导致参考失效、英文残留及第一版内容验收失败；改为旧项目的 16 kHz 单声道后本次复验正常。不能据此断言 SAM 普遍不支持 48 kHz，但生产适配必须记录完整输入条件，并在 TTS 前检查分离信号。
- 旧项目源码与当前配置可核对；历史成品存在，但任务文件未保存当时模型参数快照，不能从历史 completed 状态推断具体模型参数。

## 成果与边界

源码、MIT、uv 锁文件、报告及本地忽略的 run 产物均在关联验证目录；旧失败样片与逐请求证据保留。未写入旧项目或代码仓库，未进行 Git 交付。音色、自然度、背景纯净度需人工试听；完整原片、多人 / 配乐场景、其他模型与系统、skill 安装 / 升级均未因此验收。

下一步可基于已验证程序封装最小业务 skill，并固化媒体输入条件、分离质量检查与费用对账边界。
