# Fun-ASR 敏感词参数本地修改与音频输入边界

## 结果

用户明确要求修改 Fun-ASR 参数。关联 magicdub-skills 源码 models.py 保持 diarization_enabled=true，新增 special_word_filter：filter_with_signed.word_list 仅含“肏屄”，system_reserved_filter=false。按文件识别 API 要求以 JSON 字符串传入 SDK 和 REST。语言提示、音频预处理、上传服务保持原实现。

新项目通过模型选择取得新默认参数；已有项目保留冻结快照，不静默改写或重新计费。同步 docs/parameters.md、测试与本地 release.json 文件摘要，共 4 个文件。工作仍基于 v0.5.1，在本地未提交；未发布、安装或迁移旧项目，日常已安装 v0.5.1 尚不包含此改动。

## 验证

205 项回归通过；Ruff 通过；47 个清单文件摘要一致。新增两条模拟提交测试分别检查 HTTPS SDK 和 oss:// REST 的过滤字符串、布尔 false、说话人开关及请求头；保留旧快照拒绝响应恢复测试。未新增实际模型调用，过滤词真实云端输出未重新验证。

## 音频方案讨论

官方支持广泛格式与任意采样率，但开启说话人分离仅支持单声道。核对既有新版 Steve Jobs 90 秒样片的 Demucs 原始返回为 44.1 kHz 双声道 PCM16 WAV，工作人声为同采样率双声道 float32；因此该结果不能在保持 diarization_enabled=true 的情况下无条件原样传给 ASR。

现有 16 kHz 单声道 PCM16 副本仅统一音频格式，并非已证实的识别增强。保留原采样率与降到 16 kHz 哪个更准，尚无同源 A/B 实测结论。单声道合规结果可作为原样提交候选；双声道结果仍需处理声道。上传 URL 的选择与音频内容变换是两件事，同字节换存储不构成 ASR 质量提升证据。本轮没有更改音频处理策略。
