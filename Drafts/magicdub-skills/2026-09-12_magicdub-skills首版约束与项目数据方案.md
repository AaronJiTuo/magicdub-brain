# magicdub-skills 首版约束与项目数据方案

本文保全 2026-09-12 用户确认的要求，以及应用户要求提出的数据格式建议。第 1 节是已确认要求；其余具体目录、字段、交互和恢复机制是建议设计，尚未实现，也未因写入 Draft 自动成为正式 Release。当前 [旧规划](../../Releases/05_magicdub-skill项目规划.md) 与本次决定的差异见 [CURRENT](../../.records/CURRENT.md)。

## 1. 已确认的要求

| 事项 | 当前决定 |
| --- | --- |
| 仓库与平台 | `magicdub-skills` 技能集，独立工作流放在 `skills/<skill>/`；首版针对 Codex，自带程序直接调用 API，不依赖旧 magicdub 引擎 |
| 语言交互 | 运行时向用户提供源语言与目标语言选项；本次两段验收视频已选择英语 → 简体中文 |
| 首版译制能力 | 多人对话、声音克隆、背景音乐保留均为必需能力；继承 BGM / 环境声连续与永不做口型修正的边界 |
| 字幕 | 首版不要求交付字幕，但属于很快要做的后续版本，应能复用转写、译文和时间轴 |
| 视频长度 | 不限定短视频，使用范围包括约两小时的电影；不可将单个供应商的单次输入限制直接变成产品仅支持短视频 |
| 执行职责 | Skill 描述工作流程；Codex 理解要求、调用程序、完成首版 LLM 文本工作并协助审校；程序执行外部 API / 媒体处理、校验文本并保存状态 |
| 模型选择 | 候选清单已由用户提供，见 [候选模型](2026-09-12_magicdub-skills候选模型.md)：ASR 为 Whisper / Fun-ASR，分离为 Demucs / SAM Audio，TTS 为 IndexTTS 2；多个候选的环节列出选项，不静默切换 |
| LLM | 先使用 agent 自带 LLM，实测后再决定是否单独指定模型，不提前固定额外 LLM 供应商或要求单独密钥 |
| 模型失败 | 不静默切换模型；更换模型需要告知效果、费用影响并取得相应选择 |
| 数据基础 | 统一项目格式版本、素材身份、稳定句子编号、原文与译文、时间范围、模型参数、阶段状态和产物位置；具体字段方案见下文 |
| 原始素材 | 复制进视频项目；用户配置与视频项目仍分离，具体跨平台默认项目根目录待定 |
| 失败与导出 | 保留已完成结果、限制自动重试次数、重新导出时保留已有成品 |
| 技术栈 | Python 3.12+、FFmpeg / ffprobe、uv |
| 首批系统验收 | 先在当前 macOS 环境完成完整验收；代码保持跨平台，Windows、WSL、Linux 分别验证后再声明支持 |
| 译文原则 | 忠实原意、自然口语；可为时长调整措辞，保留关键事实、数字与人物关系，先调整译文和停顿，再考虑变速 |
| 首版质量取舍 | 质量或对齐不理想时自动继续，使用已有可用结果，不暂停请求用户裁决；最终将配音强制拉伸 / 压缩至对应原句时间窗口 |
| 首版预算 | 不提供预算设置、预算确认或按金额触发的停止机制；有限重试与逐步费用统计继续保留 |
| 费用 | 每一步记录费用，每个任务结束输出总费用；内部以 USD / CNY 分开统计，用户界面使用 `$1.20 + ¥3.40`，其中 `$` 表示美元、`¥` 表示人民币，包含失败步骤实际发生的费用 |
| 许可 | magicdub-skills 项目采用 MIT；本次记录许可决定，不代表 GitHub 已添加 LICENSE 或公开仓库 |
| 维护功能 | 加入类似 brain-template 的自动升级与请求 Star 功能；公共机制与交互建议见 [升级与 Star 方案](2026-09-12_自动升级与Star邀请方案.md)，尚未实现 |
| 安装与拆分 | 增加开始时的交互式安装配置；配置和升级采用独立 skill，与主译制 skill 分开维护，具体职责与名称建议见 [安装配置方案](2026-09-12_交互式安装配置与Skill拆分方案.md) |

首版可在执行前完成语言和模型选择后自动运行；这与“每个阶段执行完必须暂停审校”是不同能力。首版继续不要求完整审校页面或 plugin 包装。

### 1.1 首版自动继续与强制时长对齐

用户确认首版优先完成全流程；此前“质量处理不好时暂停并让用户决定”的建议不采用。

- 翻译以忠实原意、自然口语为目标，有限次数内可以调整译文与停顿；已有可用语音即使效果不理想，也继续后续处理。
- 最终配音时长必须匹配对应原句窗口。语音过长则压缩，过短则拉伸；轻微变速是优先尝试，不作为最终强制对齐的产品限制。即使所需变速幅度明显影响自然度，也自动完成，不向用户发起质量裁决。
- 对齐作用于各句配音，保留原视频画面、原有时间轴和背景轨时间位置；不能通过改变整部视频速度替代句子对齐。
- 建议实现记录生成时长、目标时长和 `tempo_ratio = 生成时长 / 目标时长`，对完整语音做时间伸缩并尽量保持音高。例如生成 5 秒、目标窗口 3 秒，则将整段配音压至 3 秒；不以直接截去后半句代替伸缩。实际长度按采样率校验，末尾仅处理样本舍入误差。
- 对明显变速、声音相似度不足等结果保留质量标记，任务完成报告说明异常；这些标记不阻止导出，也不能把“已经导出”描述为“质量验收全部通过”。
- 此规则针对有可用结果的质量问题。API 调用、下载、解码或合成失败且有限重试后仍没有可用产物时，记录技术失败、已有结果和费用，不能凭空制造成功结果；不增加人工审校决策环节，不静默切换模型。
- 首版不设置金额预算或超预算暂停。重试次数仍有上限，避免无限循环；所有实际发生的调用费用，包括失败尝试，仍进入账本。

本小节的产品取舍已由用户确认；具体伸缩算法、质量标记字段和重试次数属于实现细节，尚未实现或验收。

## 2. 建议的执行前交互

1. 读取输入视频与已有项目配置；用户本次已明确指定的参数直接采用，不重复询问。
2. 未指定语言时列出源语言和目标语言选项。源语言可提供自动识别选项，但自动识别结果仍需保存在项目中。模型不支持的语言组合不能伪装成可用选项。
3. 对存在多个已接入候选模型的阶段，列出供应商、具体模型、能力差异、计费币种与可获得的费用估算依据，由使用者选择。一个候选也需要显示实际采用的模型。
4. 模型目录由适配器维护能力声明：语言、说话人识别、声音参考、输入时长与大小限制、计费单位、用量和实账获取能力。不能只存展示名称。
5. 检查所选组合能否满足多人、声音克隆、背景音保留等要求；缺乏能力的组合不能自动降级。
6. 保存本次语言、模型、参数和价格依据快照，然后开始自动执行；正常步骤不重复弹出模型选择。

候选清单已保存在 [候选模型文档](2026-09-12_magicdub-skills候选模型.md)，不再要求用户重复提供；具体 API 参数、地域、兼容性和默认选项待实现验证。候选清单与可读文档均不能证明新 skill 已接入或账号可用，本次不发起付费调用。

### 2.1 agent 自带 LLM 的交接方案（建议）

首版 LLM 任务由当前 Codex agent 完成，因此“一次发起、自动译制”由 Skill 协调程序与 agent 共同完成，不要求单个 Python 进程自行调用宿主的模型服务。具体交接建议如下：

1. 程序根据分块 / 句子 ID 生成一批翻译输入，包含原文、时间窗口、上下文、术语、期望输出字段和源修订号，写入当前 run 的交接文件。
2. 程序记录 `needs_agent` 状态并返回交接位置；Skill 指导当前 agent 读取输入并保存结构化译文。该内部交接不等于每次要求用户手动确认。
3. 程序接收结果后核对 JSON 格式、句子 ID 覆盖、文本修订和必需字段，通过后保存正式数据并继续 TTS / 合成；不足项返回明确错误，限制修订次数。
4. 后续时长不合适需要改写时，按受影响句子在有限次数内重复交接，保留历史文字、生成结果及已发生费用；达到限次且已有可用语音后，按第 1.1 节强制对齐并继续，不转为等待用户决定。程序先释放项目写锁，agent 只写交接结果，程序重新取得锁后验证和导入，避免两个写者同时覆盖正式文本。
5. 长片分批交接并保存进度，不一次将全片原文和所有历史文本塞入上下文。实测检查译文质量、人物 / 术语一致性、长上下文遗漏和恢复后续译表现，再决定是否增加独立 LLM API。

记录文本执行来源为 `agent`，能够可靠取得模型名时保存实际值，无法取得时注明未知，不能猜测宿主模型 ID。LLM 的任务用量 / 实际费用若无法归属，则在报告中标注“宿主 LLM 费用未纳入，无法独立计量”，不显示为免费，也不把外部 API 小计冒充全部成本。将来采用独立 LLM API 时复用相同文本交接格式和账本。

## 3. 建议的项目目录

每个输入视频建立一个独立项目。以下是视频项目内部结构，不是代码仓库结构；文件名是本次建议：

```text
<视频项目>/
├── project.json
├── inputs/
│   └── source.mp4
├── data/
│   ├── speakers.json
│   └── segments.json
├── artifacts/
│   ├── audio/
│   ├── chunks/
│   ├── tts/
│   └── alignment/
├── runs/
│   └── <run_id>/
│       ├── run.json
│       ├── attempts.jsonl
│       └── report.json
├── billing/
│   └── ledger.jsonl
└── outputs/
    └── <export_id>/
        └── dubbed.mp4
```

- `source.mp4` 仅为当前 MP4 输入示例，其他输入保留正确扩展名。原始素材复制后不覆盖；复制使用临时文件，完成后核对大小和 SHA-256 再标记导入成功。
- 所有可移交的本地素材与产物路径均相对项目根目录保存；JSON 中使用 `/` 表示路径分隔，运行时由路径库解析。拒绝越过项目根目录的路径。
- API key 不进入项目；项目只记录不含秘密的供应商 / 配置引用，运行时从用户配置加载。
- 临时签名 URL 不是长期产物。需要保留的云端结果下载到项目后记录本地路径和校验值；敏感 URL 不进入普通日志或可分享报告。
- `project.json` 是入口；每次执行一个 skill 建立一个 `run_id`。中断后的继续执行关联原 run，用户显式发起重做或另一 skill 建立新 run。项目累计费用覆盖全部 run。
- `outputs/<export_id>/` 使用新标识保留每次导出。后续字幕 skill 读取同一项目数据并产生自己的导出，不能修改已有译制成品。
- 暂不预建空字幕功能，只预留共享格式；审校页以后读取和修改同一套数据。

## 4. 建议的共享数据约定

### 4.1 最小字段

| 数据 | 建议字段与含义 |
| --- | --- |
| 项目入口 | `schema_version`、`project_id`、创建时间、程序版本、输入素材路径 / SHA-256 / 大小 / 时长 / 选中音轨、源语言、目标语言、数据文件位置、run 与导出索引 |
| 说话人 | 稳定 `speaker_id`、显示名、经过选择的声音参考片段、参考素材与时间范围、使用的声音配置；供应商声音标识只是可重建缓存，不能替代本地参考素材 |
| 句子 | 稳定 `segment_id`、`speaker_id`、原视频全局 `start_ms` / `end_ms`、原文、译文、文本来源、文本修订号、质量标记、上下文关联 |
| 生成产物 | 相对路径、校验值、对应句子或分块、生成时使用的文本修订、输入指纹、模型 / 参数 / 程序版本、实际音频时长 |
| 执行记录 | `run_id`、skill 标识、状态、选定配置快照；每次尝试具有 `attempt_id`、阶段、分块或句子、外部请求编号、开始 / 结束时间、结果和错误类别 |
| 费用记录 | 关联 run / 尝试 / 外部请求、币种、金额、计费状态、计费单位及数量、价格依据、账单证据、核对时间；详见第 6 节 |

语言代码建议使用 `en`、`zh-Hans` 等明确标识；界面显示“英语”“简体中文”。时间统一以原视频时间轴上的整数毫秒保存，`end_ms` 不包含结束边界；分块只改变处理范围，不重置句子时间轴。音频精确处理另保留采样率和必要的样本偏移。

### 4.2 文本修订与跨 skill 复用

- 句子 ID 与列表下标无关，插入一句不重排已有 ID；修改文字增加修订号。
- 保留模型生成原文 / 译文和后续人工编辑的版本及来源，不能将两者覆盖成无法追溯的一段字符串。
- 拆分或合并句子建立新 ID 并记录来源关联；不能让旧配音继续错误地关联新句子。
- 配音产物引用生成时采用的译文修订号。译文变化后，旧配音仍保留，但标记为不再适用于当前版本；对齐、混音和成品有效性随依赖重新判断。
- 字幕 skill 读取选定文本修订和时间轴；说话人、语言、文本与时间信息不依赖任何一家供应商响应格式。
- 文字快照与执行 / 费用流水分开。建议 V1 使用 UTF-8 JSON + JSONL，不为首版引入数据库。
- 同一项目默认单写者：程序持有可恢复的项目锁，快照采用临时文件加原子替换，流水追加后持久化。未来审校保存带基础修订号，冲突时不覆盖另一份修改。
- `schema_version` 独立于 skill 发布版本；不认识的新格式明确停止写入，升级格式前保留旧快照。

上述机制是实现建议。用户已确认统一数据基础，但没有逐项确认此处的具体字段名、文件名或修订实现。

## 5. 长视频与恢复设计建议

约两小时电影属于目标使用范围，应从首版架构中考虑：

- 音频按所选模型的实际限制分块处理，保存分块起止时间和边界处理信息；不默认把整部电影一次上传给每个模型。
- 跨块统一说话人身份与声音参考，不能把同一人每一块识别成新说话人；翻译保留必要的上下文、人物和术语信息。
- 以全片时间轴进行回填和混音，边界重复、漏句、累计偏移、尾句截断与背景轨连续性是专门验收点。重叠语音允许表达为时间范围重叠的多个句子，处理异常须显式标记，不能悄悄丢弃某个说话人。
- 使用有限并发和磁盘文件处理，不一次启动所有句子的 API 请求或将整片处理产物全部加载到内存；导入、临时音轨和多次导出前检查磁盘空间。
- 每个阶段、分块或句子及时保存状态；续跑先检查输入、文本修订、模型参数和产物完整性，再复用成功结果。
- 外部请求提交前写入本地尝试标识，得到远端请求编号后立即持久化。供应商支持幂等标识时使用它；若断线发生在远端接收后、本地拿到编号前，则标记提交结果不明，不能自动当作未提交重试。
- 远端仍执行的任务继续查询，不把本地超时等同于云端取消。重试上限作用于实际新提交的尝试；轮询不得被计作新的模型调用。

两段当前样本能够验证中等时长流程，但不足以证明约两小时电影、多人对话或复杂背景音均已通过。保留用户指定样本，后续补充相应场景的验收证据；本次不另选或生成新的验收媒体。

## 6. 按调用计费、按币种汇总的方案

### 6.1 账本粒度与范围

费用必须覆盖所有执行尝试，包括成功、失败、取消、结果不明，以及配音时长不合适引发的付费改写 / 重生成。阶段成功与否和请求是否收费是独立状态。

首版不设置任务预算、金额上限或超预算暂停；这是执行范围的简化，不取消逐步记账、费用来源区分和结束汇总。

- 每次收费操作建立费用项，至少关联 `run_id`、`stage`、`attempt_id`、供应商和外部请求编号；句子级重试另外关联 `segment_id`。
- 若同一请求含多个计费组成部分，使用独立费用项或供应商费用明细标识；不能简单按请求 ID 去重后丢掉真实费用。
- 请求状态查询、重复读取账单或同一事件的回传不得重复累加费用。供应商内部重试按其实际账单处理，不依据 SDK 日志中的重试次数自行乘价。
- 缓存命中不新增模型费用；历史费用仍计入项目累计，不重复计入本次新 run。失败后补交付成品不删除前面失败尝试的费用。
- 与任务直接相关、能归属到具体操作的 API、云端处理、存储与传输费用进入账本。不能归属或无法取得的项目标明统计覆盖范围，不能说“所有成本已完整核实”。Codex 订阅 / 宿主侧模型费用不凭空分摊；只有取得明确任务用量与计价依据时才另行纳入。
- 充值不是本次任务费用；折扣、免费额度、抵扣与退款依据供应商记录处理，保留标价 / 折扣 / 实际用量费用的区分。退款以可追溯的调整项记录。

### 6.2 金额与状态

建议费用项保存以下核心数据：

| 字段 | 约定 |
| --- | --- |
| `cost_item_id` / `revision` | 稳定费用项标识与账本修订号；同一项对账后更新有效修订，历史行保留 |
| `currency` | 原始计费币种，如 `USD`、`CNY`；金额未知且币种也未知时单列，不猜测 |
| `amount` | 十进制字符串，例如 `"0.001250"`；未知为 `null`，不能写 `"0"` |
| `status` | `confirmed` 已获得供应商可归属费用依据；`estimated` 按用量 / 单价估算；`pending` 金额待核实 |
| `source` | 供应商账单 / 费用响应、用量乘单价、人工导入等来源；保留必要证据标识和查询时间，不保存凭证 |
| `usage` / `pricing_snapshot` | 用量、单位、适用单价、币种与价格生效 / 查询时间；避免以后按新价格回算旧任务 |
| `attempt_id` / `request_id` | 本地尝试与远端请求关联；一个账单费用不能同时被归入两个 run |

Python 使用 `Decimal` 运算，先按币种和有效费用项求和，再按展示精度格式化；不能逐句四舍五入到两位后相加。账本仍保存 `USD` / `CNY`，用户展示采用 `$金额 + ¥金额`。加号表示两种币种并列，不执行跨币种相加或默认换汇；`¥` 在本项目明确指人民币。未来如增加折算，只作为带汇率、时间和来源的附加视图，原始账本不变。

`billing/ledger.jsonl` 建议保存追加式费用事件。每个事件有唯一事件 ID，同一 `cost_item_id` 只有最新有效修订参与汇总；不能将同一项的估算和后来的确认金额累加两次。运行报告从账本派生，带生成时间与账本版本，可在对账后重新生成。

零费用也需要依据：纯本地处理可标注“无外部 API 费用”；供应商明确未收费可记录零。失败、取消、暂未查到账单或缺少查询权限均不能自动推断为零。

### 6.3 任务结束输出

任务成功、失败或正常取消，都输出执行状态、产物位置、阶段费用与任务费用汇总；强制终止来不及输出时，下次打开项目或查询状态补出报告。项目累计和本次任务必须分开，避免重跑历史费用看起来像本次新增费用。

以下金额仅演示输出形式，非本项目实测费用：

```text
任务状态：失败，已有转写和译文保留
本次任务已确认费用：$1.20 + ¥3.40
其中失败尝试费用：$0.20 + ¥0.60（已包含在上行）
另有估算费用：$0.08 + ¥0.10
金额待核实：1 笔，当前费用尚未完整核对
项目累计：按 $金额 + ¥金额 展示，并分别注明确认 / 估算 / 待核实状态
```

逐阶段明细使用同样口径，可展开到每次尝试。统计范围内所有费用确认后，显示“本次任务总费用：$… + ¥…”，同时注明统计覆盖范围。存在估算、未知金额或宿主 LLM 无法计量等情况时也必须输出费用摘要，但不能将已确认的外部调用费用冒充覆盖全部成本的精确最终总额。

### 6.4 fal 计费接口的当前证据与权限边界

2026-09-12 核对的 [fal Billing Events 官方文档](https://fal.ai/docs/platform-apis/v1/models/billing-events) 支持按请求查询，返回 USD 费用明细（含折扣前后金额），并注明需要 Admin API key。按请求匹配适合用于对账；本次只核对文档，未验证实际账号权限、数据延迟或调用结果。

建议普通推理继续使用其所需权限的 `FAL_KEY`。用户若选择自动对账，另在本机配置可读取账单的凭证；具体配置名待实现，不升级普通推理凭证或要求把密钥发送到聊天。没有该权限时，保留估算 / 待核实状态，并支持以后补充账单核对。其他供应商的计费来源与权限需随候选清单逐个核实。

fal 的 [队列文档](https://fal.ai/docs/documentation/model-apis/inference/queue) 支持保存请求 ID 后从其他进程查询状态与结果，为断线后的任务追踪提供接口基础；这不保证所有失败任务免费，也不代表本项目已实现恢复功能。
