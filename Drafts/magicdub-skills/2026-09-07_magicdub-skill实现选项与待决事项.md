# magicdub-skills 实现选项与待决事项

本文始于 2026-09-07 的规划讨论，2026-09-12 按用户确认更新待定状态，不是完整聊天记录。既有正式基线见 [项目规划](../../Releases/05_magicdub-skill项目规划.md)；新确认的要求与数据设计建议见 [首版约束与项目数据方案](2026-09-12_magicdub-skills首版约束与项目数据方案.md)。新决定尚待同步到 Release，具体设计建议不会因整理入档自动成为已确认选型。

## 分期原则与最新调整

- 首版针对 Codex，输入视频后自动执行主 pipeline，交付译制完成的新视频。
- 通过 skill 自带程序直接调用供应商 API，不依赖既有 magicdub 引擎。
- 2026-09-12 已将部分环节的候选模型选择提前到首版；中间文本修改与可视审校继续迭代。首版不要求字幕，但字幕属于近期后续版本。
- 仓库定位已调整为技能集，独立工作流放在 `skills/<skill>/`；首版先开发译制 skill，未来是否增加 plugin 包装根据实际分发需求决定。
- 早期自用，未来较大可能公开；不把当前电脑的个人路径作为安装前提。

原始分期原则曾进入 Release，技能集定位和上述新调整尚未同步；漂移见 [CURRENT](../../.records/CURRENT.md)。

## 1. 程序语言与运行依赖

2026-09-12 用户已确认 Python 3.12+ 负责 API 调用、流程执行和项目状态，FFmpeg / ffprobe 负责媒体处理，uv 负责 Python 环境与依赖管理。

首批完整验收已确定为当前 macOS 环境；保持代码跨平台，Windows、WSL、Linux 分别验证后再声明支持。依赖安装方式和 FFmpeg 获取方式仍需落实，最低 Python 版本已经确定。只安装新 skill 及其声明的依赖，不能要求用户另行安装旧 magicdub 引擎。

后续审校页面考虑 HTML / JavaScript。前端语言不要求 pipeline 使用同一种语言；是否采用前端框架、是否需要构建工具，取决于首个审校原型的实际复杂度。

## 2. 工作目录

讨论中的布局建议：

- 全局配置和可清理缓存可放在 `~/.magicdub/` 一类应用目录。
- 每个视频使用一个用户可见的项目目录；讨论示例为 `~/Movies/MagicDub/projects/<项目名>/`，同时允许指定其他位置。
- skill 安装目录只承载指令、程序和静态资源；项目素材与成品独立保存。

这些路径只是候选，没有确定为跨平台默认值。用户已确认配置与项目分离，并在 2026-09-12 选择将原视频复制进项目。建议项目内保存相对路径和素材校验信息；默认根目录、缓存清理和命名冲突仍待定。不能把“项目状态独立于聊天”误写成“未落地验证的项目迁移功能已经可用”。

## 3. 审校页与本地服务

后续候选方案为轻量 HTML / JS 页面，提供原文与译文对照、视频定位、逐句试听、文本修改与保存。

- 只读展示可以先做静态页面原型。
- 需要稳定读取项目媒体、把编辑保存回文件或请求重做片段时，建议由随 skill 分发的小型本地 HTTP 服务提供页面和接口。
- 服务按审校需要启动，默认仅监听本机回环地址；不作为首版自动译制的运行前提。
- 页面通过服务访问所选项目，供应商凭证由执行程序使用，不写进前端脚本。
- Codex 负责提示当前待审校步骤；用户保存后回到对话继续，页面修改与执行程序需要共享项目状态。

Codex 中打开页面的具体入口、进程保持方式、浏览器与媒体播放能力尚未做本项目原型验证。实施时再核对所支持 Codex 客户端的能力，并提供系统浏览器入口；不能承诺安装 skill 后会自动出现原生 UI 面板。

落地前还需确定：文本保存接口、编辑版本冲突处理、重做片段是否由页面触发、长任务进度通知，以及关闭审校后的进程回收。

## 4. 安装与 plugin 包装

仓库已改名为 `magicdub-skills`，按视频译制、字幕等独立工作流组织 `skills/<skill>/`。用户进一步要求开始时的交互式安装配置，并将配置、升级从主 skill 拆开；建议首版为 `magicdub`、`magicdub-setup`、`magicdub-upgrader`，名称和具体职责见 [拆分方案](2026-09-12_交互式安装配置与Skill拆分方案.md)。不按内部 pipeline 阶段机械拆分 skill。

具体安装目录和安装命令尚未确定；用户已要求加入类似 brain-template 的自动升级与请求 Star 功能，见 [维护方案](2026-09-12_自动升级与Star邀请方案.md)。拆分交互入口后仍共用底层程序：setup 连续完成依赖、目录与所需凭据配置，upgrader 负责稳定升级；业务中自动检查后按用户指令升级，成功安装或升级后可选邀请 Star。安装方式与具体策略在实现时验证。未来如需统一安装、依赖或扩展分发，再评估 plugin 包装，插件安装由宿主更新机制管理。增加包装不应要求改写 pipeline 或项目数据格式，也不要求提前改仓库名。

2026-09-12 已选定 MIT 许可证；公开时间、安装分发与发布渠道仍未定。许可选择不代表已在 GitHub 添加 LICENSE，也不构成将私有仓库公开的授权。

## 5. 首版需要用实现验证收敛的参数

- 候选已由用户提供，见 [候选模型](2026-09-12_magicdub-skills候选模型.md)：ASR 为 Whisper / Fun-ASR，音频分离为 Demucs / SAM Audio，TTS 为 IndexTTS 2；默认选项与接入待实测。LLM 先使用 agent 自带模型，实测后再决定是否单独指定；不得沿用旧草稿强制接入外部翻译 API。
- 已指定两段验收素材 `test_by_step/source/stevejobs.mp4` 与 `test_by_step/source/trump_full.mp4`，方向为英语 → 简体中文；媒体核验信息见 [最新方案](2026-09-12_magicdub-skills首版约束与项目数据方案.md#7-已指定的验收素材)。
- 首批 macOS 验收的输入格式、输出编码规格与其他系统后续验证；范围包含约两小时电影，需落实分块与长片验收，不能继续作为只支持短视频规划。
- 强制时间伸缩算法、采样级长度校验、翻译与 TTS 的有限重试次数。译文忠实自然，先调措辞 / 停顿，最终强制将配音拉到原句同等长度；有可用音频时质量问题不暂停、不请求用户裁决。
- 对账能力、媒体中转组合及过期处理；首版已明确不设置预算或超预算暂停。逐步骤记账、包含失败费用继续保留，用户展示为 `$金额 + ¥金额`，账本仍用 USD / CNY。fal CDN 与百炼临时存储已列为候选，SDK / REST 按已确认的媒体地址规则匹配；宿主 LLM 费用无法独立计量时单独说明统计缺口。

不能直接照搬旧引擎配置，将旧项目曾用过的 API 或历史成功任务视为新 skill 已验证能力。
