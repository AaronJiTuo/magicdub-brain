# 多音轨与多声道处理方案

用户提出“分开提取每条音轨、每个声道，各自处理后合并”，并询问是否合理。本文保全技术分析与建议；未将逐声道完整译制确认为首版默认，也未进行模型或多声道混音实测。已确认的产品要求仍按 [正式规划](../../Releases/05_magicdub-skill项目规划.md)执行。

## 1. 可以提取，但先区分三个层次

| 层次 | 含义与例子 | 处理判断 |
| --- | --- | --- |
| 音轨 / 音频流 | 容器内多个音频流，可能是原声、另一语言配音、评论音轨，也可能是不同录音素材 | 先确定内容和用途；替代版本通常保留为可切换音轨，不把它们混在一起 |
| 声道 | 一条音轨里的左、右、中置、环绕等通道 | 声道布局说明空间通道，不保证一人一声道或只有某类声源 |
| 独立声源 / 分轨素材 | 单独的对白、音乐、音效，或独立收音的不同人物 | 有真实独立源时可分别处理并按原关系混合，是比单纯按声道切分更直接的译制材料 |

FFmpeg 的 `-map` 可以选择音频流；`channelsplit` 可以把一条音频流的各声道输出成独立流，`join` / `channelmap` 可按映射重组声道。重新封装多条音轨、重建一条多声道音轨、把对白和背景相加是三种不同操作，不能一律理解为混音。

这说明“分开提取”可实现；不说明每个输出都应分别做一遍 ASR、翻译和 TTS。分离前已损失的信息不会因声道拆开而恢复，保存为无损文件也不能恢复源文件此前压缩丢失的信息。

## 2. 为什么逐声道独立译制未必更好

以左右声道都包含同一句对白的立体声为例：如果分别转写、翻译并生成配音，就可能得到措辞、停顿或音色不同的两份结果。即使两份都强制到相同总时长，句内节奏也可能不同，重组后会出现重声或空间位置不稳。这是根据独立生成流程推导的风险，不是当前模型的实测结论。

5.1 / 7.1 的通道也不是人物分轨。不能将所有声道都当作人声送去译制，亦不能假定删掉中置便得到完整背景：Dolby 的译制案例明确描述，中置通道同时包含对白与音乐 / 音效，移走对白时需要补回受影响的声音元素。该案例是对“中置一定是纯人声”的反例，不表示每部电影的混音方式完全相同。

独立分离各声道可以作为候选方法，但是否优于整轨处理取决于素材和模型。比较时需检查跨声道音量、延迟、相位关系和空间听感，不能按调用次数或价格判断最好。

## 3. 建议的处理顺序

1. 读取音轨列表与声道布局，保存来源、语言标签、采样率、时间起点和声道映射；必要时试听，不能从轨道序号猜用途。
2. 对需要译制的音轨分别建处理分支；原声、其他语言和评论轨作为独立版本管理，不自动混播。是否需要全部处理由任务目标决定。
3. 保留所选音轨的原始多声道材料，按需要提取分析副本。避免在一开始就不可逆地把所有空间信息压成单声道并丢掉原始结构。
4. 识别独立对白内容及说话人，跨声道去重并形成统一文本 / 时间轴；对同一语句和说话人生成一份对应配音，再按需要回填多个声道。真正不同人物的独立收音可分别识别和生成，但仍共享上下文、人物映射和全片时间轴。
5. 对含对白的通道移除原对白并保留或修补背景；只处理中心通道是否足够应按素材验证。对已确认无对白的背景部分尽量复用。
6. 将生成配音按目标空间位置、音量和必要混响回填，与保留的背景按明确声道映射重组；最后按用户目标封装成一条或多条输出音轨。

上述是在保留原始声道结构的基础上统一处理对白的候选路线，不等同于保证恢复原片全部空间声场；具体模型对多声道的输入输出能力及回填方法仍需实测。

## 4. 哪些素材适合真正分别处理

- 两个人分别录在左、右声道，且不是同一人声的重复混音：分别处理有价值，同时检查串音和重叠。
- 有独立对白与音乐音效素材：优先利用这些源，保留背景，只替换对应对白；源分轨本身也可能是多声道。
- 一份文件里有多种语言 / 评论音轨：可以分别导出和译制，但交付应保留版本关系，不把所有译制语音叠在同一音轨。
- 仅有普通立体声或环绕混音：是否逐声道分离需要 A/B 比较；ASR、译文与 TTS 仍应建立统一的对白关联，不按声道数机械重复生成。

提高质量所需的额外费用沿用项目账本逐次记录，包括失败尝试；仍不设置预算门槛。本轮没有付费调用。

## 5. 验证建议与来源

用同一段有代表性的素材比较整轨处理、逐声道分离后统一对白处理，以及存在真实分轨时的独立源处理。固定译文、声音参考和所选模型，记录对白残留、背景损伤、左右 / 环绕一致性、重声和时间轴情况；多声道与下混播放都应试听。

用户指定的两段现有验收视频只有一条双声道音轨，未据此确认两声道是否独立收音，也未提供 5.1 / 多音轨验证证据。因此不能在本轮直接选择一种方法并宣称质量最好。
