# magicdub-skills 交互式安装配置与 Skill 拆分方案

用户要求增加开始时的交互式安装配置，并将配置、升级等维护流程从主 skill 拆出，以控制单个 skill 的复杂度和长期维护成本。此方向已确认；下文的名称、安装方式和具体向导步骤是建议设计，尚未实现或进入正式 Release。上一轮“不必新增独立 skill”的建议不再采用，共用底层程序的原则继续保留。

## 1. 首版职责划分

| 建议 skill 名称 | 职责 | 边界 |
| --- | --- | --- |
| `magicdub` | 视频译制、语言与模型选择、进度、成品和费用交付 | 仅做简短环境预检与必要路由，不包含完整安装和升级指南 |
| `magicdub-setup` | 首次安装、依赖准备、交互配置、配置修改、自检与未完成设置恢复 | 重复配置保留已有资料；不因再次 setup 自动升级程序 |
| `magicdub-upgrader` | 版本检查、升级、升级中断恢复和结果验证 | 普通业务中只调用轻量检查；明确升级指令后才加载完整升级流程 |
| `magicdub-subtitles`（后续） | 使用同一项目的文字与时间轴制作字幕 | 不重复维护安装、凭据和升级流程 |

安装配置与后续配置修改共享同一套读取、修改、校验动作，首版可归于 setup；升级涉及版本来源、切换和恢复，独立为 upgrader。先交付三个实际需要的 skill，字幕随后增加，不预建更多空入口。

每个 skill 有独立的 `skills/<名称>/SKILL.md`，描述中明确触发词和范围。主 skill 遇到“修改密钥”“修改项目目录”等请求时按需读取 setup；遇到升级请求时读取 upgrader。无须让用户记住或手动切换 skill 名称，也不需要启动另一个 agent 或另开会话。

Codex 官方文档说明，技能先以名称和描述被发现，选中后再读取完整 SKILL.md，并建议单个 skill 聚焦一个工作。这里只借鉴按需加载机制，不承诺任意客户端都会按某种固定界面自动跳转。来源：[OpenAI Docs — Build skills](https://learn.chatgpt.com/docs/build-skills)，2026-09-12 核对。

## 2. 用户最初从哪里开始

README 建议提供一句自然语言安装入口：

> 请安装并配置 MagicDub：https://github.com/shishengkai/magicdub-skills

这是未来入口文案，不是当前已经可用的安装命令。

首次安装时这些 skills 尚未被宿主发现，因此 README 必须指向同一版本源码中的 setup 指令及引导程序；Codex 取得并核验该版本后显式读取指令，执行依赖准备及安装。不能让一个尚未安装的 skill 依赖自身已经自动触发，也不能让引导程序先依赖还没装好的 Python 包或 uv。

独立安装需要同时交付基础维护 skills、所选业务 skill 及其运行程序，并验证 Codex 实际能发现入口。仓库的 `skills/` 是源码布局，不等于任意 clone 到本地后都会被 Codex 自动扫描。具体使用本地 skill 安装能力还是自带引导程序，以及目标注册路径，实施时在支持的 Codex 客户端实测。

同一版本内的公共代码、引用和依赖需要随安装完整交付，不能只复制一个 SKILL.md 后仍依赖开发者电脑的相邻源码目录。尚无稳定 Release 时，开发试用应明确标注并固定 commit；不能因稳定通道失败自动降级到 main。

## 3. 首次安装配置向导

首版采用 Codex 对话提问与状态展示，不需要配置网页或 Web server。宿主能提供选项时用选项，否则使用简短文字问答；一次只收集当前缺失的一组信息。

1. **探测已有状态。** 识别实际执行环境为 macOS、Linux、Windows 原生或 WSL，检查当前安装来源、版本、已有配置、Python 3.12+、uv、FFmpeg / ffprobe 和目录权限。跨平台仍遵守先验收 macOS、其他系统逐一验证的范围。
2. **准备运行依赖。** 复用兼容依赖，缺失时按目标平台的明确方案准备。默认使用 MagicDub 管理的运行环境，不替换系统 Python 或升级无关软件。若环境限制需要用户操作，说明一个具体动作及原因，不让用户自行编排整份工程命令清单。
3. **确定项目位置。** 展示适合当前系统的默认候选，让用户选择默认位置或自定义文件夹；已有选择直接复用。配置目录、安装目录和视频项目目录分离，跨平台具体默认值仍待定，不询问用户内部缓存和锁文件放在哪里。
4. **补齐所需服务配置。** 检查已有凭据是否可供执行程序使用，只显示配置状态与来源，不显示值。根据当前要启用的模型收集缺项：fal 模型需要 `FAL_KEY`，启用百炼 Fun-ASR 时再配置 `DASHSCOPE_API_KEY`；不为未使用的供应商一次索取全部凭据。首版宿主 LLM 不需要额外 LLM key。
5. **完成验证并交接。** 校验配置格式、实际路径与可写性，执行本地依赖和入口自检；供应商支持合适的非生成鉴权检查时验证连接，否则注明“已填写，调用权限待首个真实任务验证”。输出可用组件、路径、缺项和下一步；不把“安装配置就绪”写成“两段视频验收通过”。

密钥输入优先使用宿主已提供且经过验证的受保护入口；没有时生成本地凭据模板，打开或指出具体文件供用户填写，程序重新读取并只返回状态。不能要求用户把 key 发到普通聊天。首版不为密钥配置额外建设网页。

安装时可保存常用模型偏好，但不强迫用户立即选择所有视频的语言或固定全局模型。每个视频仍按已确认要求展示已接入候选，用户本次已经指定的选择直接沿用。配置向导只在选用新增供应商时补相应凭据，不重复从头安装。

单纯安装与配置不自动开始付费模型生成。用户请求“安装并译制这个视频”时，安装完成后继续该已授权任务；请求仅为安装时，完成后交付可用入口。任何验证若实际产生费用，也必须逐次入账并按 `$金额 + ¥金额` 汇总，失败费用包括在内。无视频项目的维护验证使用用户级维护记录承接同一计费格式，不伪造视频项目或漏记费用；宿主 LLM 无法计量时说明覆盖范围。

## 4. 重复配置和业务续接

- setup 必须可重复运行：重新读取现状，只补缺项或修改用户指定字段；不重置密钥、模型偏好或项目目录，不创建第二套无关安装。
- 安装中断后从已完成状态继续，保留已下载且验证通过的版本及原配置。程序输出缺少依赖、缺少配置、入口未生效等明确状态，agent 按返回结果推进，不能凭一个手填的 `configured=true` 宣称成功。
- 普通配置按字段更新、校验后原子写入；必要时保留原配置。配置改变主要影响新任务，已有任务按自己的配置快照执行；不自动移动全部历史视频项目。
- 主 skill 提交模型任务前运行轻量预检。缺少 Fun-ASR key 时只进入 setup 的凭据补齐路径，补齐后回到原视频的原步骤，不丢失语言、模型、输入位置和已完成结果。
- 项目及待办信息保存在文件中，支持换会话后恢复；配置与升级通过安装记录找到实际程序和引用，不依赖 agent 永久记住此前聊天。

## 5. 共享实现与维护后置步骤

skill 拆分的是交互职责，Python 程序仍由本项目统一实现并随版本分发。安装探测、配置读写、版本校验、数据协议、API 适配和费用账本各自保持单一实现；不能在三个 skill 中复制三套同类程序，也不引用旧 magicdub 引擎。

业务 skill 仅保留“开始前预检、任务完成后调用轻量版本检查”的短规则。版本筛选和升级操作细节由 upgrader 及程序维护；不能为每次轻量检查都将全部升级长文加入业务上下文。

Star 继续复用一份公共规则，不单独创建 Star skill。为贴合安装 / 升级拆分，建议改为首次安装配置全部成功、或真实升级成功后判定邀请；普通译制、改配置、自检、重复安装和失败不邀请。其可忽略、独立同意后执行、回读确认、不影响功能的边界不变。该触发调整属于本次建议，替代上一轮首个视频完成后邀请的设想。

未来 plugin 可以封装这些独立 skills 和共享程序；职责划分继续保留，安装升级仍遵守宿主对 plugin 的管理边界。首版无需先实现 plugin。

## 6. 首批验收建议

- 全新 macOS 安装，从 README 入口到基础 skills 可发现、依赖和所需配置就绪；引导过程没有未声明的先决工具。
- 已安装后重复 setup、只改一个字段、中断后继续，均保留已有配置和视频资料；设置流程不悄悄升级程序。
- 未配置时直接发起译制，补齐缺项后继续同一视频；已配置时日常译制不重新询问全部安装问题。
- 选 Fun-ASR 时补百炼配置；仅用 fal 的组合不要求百炼 key；已有 key 不回显或再次索取。
- Codex 在新任务中可发现三个入口，运行程序及共享引用均来自完整安装包；拆分后的路由和相对路径经过真实加载验证。
- 升级仅加载对应流程，维护失败不制造成功；Star 只在相应成功事件后判定，确认升级不等于确认 Star。
